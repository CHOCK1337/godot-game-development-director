# Producing Game Content

## Core rule

A content plan is a promise about player-visible experience, not a list of assets. Every item needs purpose, owner, dependencies, acceptance evidence and a removal path.

## Workflow

1. Define one observable player experience and 3–5 content pillars.
2. Split Must/Should/Could/Won't; cap blocking items at three.
3. Build one Vertical Slice that proves gameplay, content tools, save, audio, UI and QA together.
4. Assign each content unit stable ID, owner, inputs, dependencies and exit criteria.
5. Freeze interfaces before multiplying content variants.
6. Cut low-leverage content before compressing testing and polish.

## Deliverables

Content pillars, scope table, dependency map, milestone exit criteria, risk register, cut order and Definition of Done.
