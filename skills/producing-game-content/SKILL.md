# Producing Game Content

## Boundary / 边界

Own scope, content inventory, dependencies, milestone exit criteria, freeze, risk, and cut order. Do not overrule specialist facts about design, implementation, art, audio, accessibility, or QA.

负责决定这一阶段做什么、何时冻结、什么先删；不替代专业领域结论。

## Required evidence / 所需证据

- Observable player outcome, team/capacity, milestone date or budget, current content inventory, dependencies, and known blockers.
- Representative vertical-slice path and the tools/save/UI/audio/QA needed to ship it end to end.
- Evidence for completion, not percentage estimates without a Definition of Done.

## Core rule / 核心原则

A content plan is a promise about player-visible experience, not a list of assets. Every item needs purpose, owner, dependencies, acceptance evidence and a removal path.

## Workflow / 工作流

1. Define one observable player experience and 3–5 content pillars.
2. Split Must/Should/Could/Won't; cap blocking items at three.
3. Build one Vertical Slice that proves gameplay, content tools, save, audio, UI and QA together.
4. Assign each content unit stable ID, owner, inputs, dependencies and exit criteria.
5. Freeze interfaces before multiplying content variants.
6. Cut low-leverage content before compressing testing and polish.

## Deliverables / 强制输出

Content pillars; Must/Should/Could/Won't table; stable content-unit IDs; owners and dependencies; vertical-slice path; milestone entry/exit gates; freeze rules; top-three blockers; risk register; cut order; Definition of Done; validation evidence.
