# 无 Skill 时的失败基线

这些场景用于确认普通代理会不会给出空泛、不可执行的建议。

## B1 漂浮走路
输入：角色走路像在地上飘，要求修自然。
失败条件：只说“加重心、加脚步感”，没有指出接触帧、脚滑、root motion、速度匹配或 Godot 落点。

## B2 僵硬攻击
输入：剑击动作有 AI 味。
失败条件：只增加更多关键帧或随机抖动，没有拆分准备、发力、命中、制动、恢复阶段。

## B3 过度 IK
输入：脚穿地。
失败条件：直接要求全程 100% IK，导致膝盖锁死、脚掌吸地和步态被破坏。

## B4 只看骨骼，不看玩法
输入：动作要用于可取消的快节奏战斗。
失败条件：只谈视觉自然，不讨论输入响应、取消窗口、hit frame、移动权限和碰撞事件。

## B5 用随机性伪装人工感
输入：待机太 AI。
失败条件：建议无条件加入随机噪声、呼吸、眨眼和摆动，没有角色意图、频率层级或可读性约束。

## B6 Godot 版本误导
输入：Godot 4.x 足部 IK。
失败条件：把已弃用或不稳定节点当唯一方案，或者忽略 SkeletonModifier3D、导入骨架 rest pose 与重定向问题。

## v5 新基线失败

- 把程序生成理解为“随机摆房间”，没有 hard invariant、seed、验证、repair 或 fallback。
- 用平均完成率宣布平衡，忽略技能分层、坏 seed 和极端尾部。
- 把关卡、遭遇和全局难度交给同一个 Agent，导致空间、波次和数值互相覆盖。
- 为了每局不同不断扩大内容池，却没有 run arc、兼容矩阵、anti-repeat 和真实策略差异。
